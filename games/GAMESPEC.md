# Verse Games: Game Authoring Spec

How to add a new game to the library. Three steps, nothing else.

## 1. Write the data file

Create `js/data-<id>.js`. Copy the shape of `js/data-plagues.js` (knowledge game)
or `js/data-joseph.js` (narrative journey). Register with:

```js
VG.register({
  id:"<id>",                 // unique, lowercase, no spaces
  title:"<Title>",
  kicker:"KJV · <range>",    // e.g. "KJV · Genesis 37–50"
  source:"<range>",
  desc:"<one or two sentences, formation voice>",
  meta:"5 stages · 20 questions · three-strike",
  shelf:"knowledge",         // or "narrative" for a journey
  playable:true,
  art:"img/card-<id>.webp",  // 16:8 cartoon card, bright friendly style
  seal:{ref:"<ref>", verse:"<exact KJV>"},   // knowledge games: closing verse
  stages:[ {name:"Stage 1 · <Name>", questions:[ ... ]}, ... ]
});
```

Question shape:

```js
{q:"<question>", options:["<correct first>","<wrong>","<wrong>","<wrong>"],
 a:0, ref:"<Book 1:1>", verse:"",   // leave verse:"" empty; the fill tool fetches exact KJV
 insight:"<one or two sentences, drawn from this verse, formation over flash>"}
```

Rules:
- The correct answer is always `options[0]` with `a:0`. The engine shuffles at play.
- Every question must have a real `ref`. Never invent a reference.
- `verse:""` stays empty in the source; `node tools/fill-verses.js` fills exact KJV text from bible-api.com. Verify the fill output.
- No em dashes or en dashes anywhere, including in verses (the fill tool scans for them).
- Insights teach from the specific verse, never a generic moral.
- Knowledge games: 5 stages, 3 to 4 questions each (15 to 20 total).
- Narrative journeys: 5 stages; each stage has `title`, `teaser`, `ref`, `text` (2 to 3 short paragraphs), `img` (16:8 scene art), and a `gate` of 3 questions.

## 2. Add the script tag

In `index.html`, add one line after the other data files:

```html
<script src="js/data-<id>.js"></script>
```

`tools/build-dist.js` and `tools/fill-verses.js` auto-discover `js/data-*.js`; no other registration needed. The hub renders the card from the registry automatically.

## 3. Build, fill, test

```bash
node tools/fill-verses.js                       # fetch exact KJV text for new refs
node tools/build-dist.js                        # dist/verse-games.html (code only)
python3 tools/inline-images.py dist/verse-games.html 720 72        # full-size art into dist
VG_SLIM=1 node tools/build-dist.js verse-games-slim.html           # slim code bundle (Genesis 1-10 only; campaigns excluded)
python3 tools/inline-images.py dist/verse-games-slim.html 224 40   # small art into the slim bundle
python3 tools/make-widget-preview.py dist/verse-games-slim.html dist/widget-preview.html   # under 1MB
node tools/test-all.js                          # must end with ALL TESTS PASSED
node tools/test-all.js dist/widget-preview.html # slim preview must also pass
```

## Card art

- `img/card-<id>.webp`, bright friendly 3D cartoon style matching the library.
- All art must be original. Never copy an image of unknown copyright into the build.
- If image generation is policy-blocked for a subject, use a painted CSS/SVG motif instead (see `.vg-art-plagues`) and do not retry.
- Journey stage scenes: `img/<id>-<stage>.webp`, same style.

## Campaign game mode (beyond stages and journeys)

A game can play by its own rules instead of the standard stage shape.
Register with `shelf:"mix"` and `mode:"whosaidit"`, and give it a `levels`
array (`{name, questions:[{q, options, a, ref}]}`) instead of `stages`.
The engine routes `mode:"whosaidit"` games to their own screens
(campaign panel, rounds, unlocks) without touching standard games; add new
screens in the `who said it` section of `js/engine.js`, new styles prefixed
`.wsi-` in `css/verse-games.css`, and keep the hub's "game mix" shelf honest.
Large campaign data ships in the full site bundle only: extend the
`VG_SLIM` filter in `tools/build-dist.js` so the widget preview stays under
1MB. The reference implementation is Who Said It (`js/data-who-said-it.js`,
generated by `tools/gen-who-said-it.js` from the verified quote bank;
verified by `tools/test-who-said-it.js`).

A second campaign reference is King Solomon (`js/data-solomon.js`,
generated by `tools/gen-solomon.js` from the original King Solomon app's
adult/KJV case files; verified by `tools/test-solomon.js`). It registers
with `mode:"solomon"` and a `scrolls` array (`{name, cases:[...]}`, each
case carrying its own unique illustration in `image`). Its engine section
(`sol*` in `js/engine.js`) implements the discipline loop: Scroll One is
gentle with no failure effects; from Scroll Two a wrong judgment shows
its consequence in the story, costs 5 wisdom and 1 standing, and the
player must fill in the missing proverb words, checked word for word
against the proverb text, to appeal and retry. New campaign modes follow
the same pattern: own `mode` string, own engine section, own `.xxx-`
CSS prefix, own generator + test, and an entry in the `VG_SLIM` filter.
